# HopWorld iOS 开发文档

文档日期：2026-11-13。状态：只定范围和边界，尚未建立 iOS Target，也没有移动或修改任何 Mac 源码。

用户看到的名称仍是**跃界**。英文产品名仍是 HopWorld。iOS 是同一产品的薄客户端，不是另一个品牌。

Mac 的协议范围、内核分工和字段限制以仓库里的 [支持列表](../docs/支持列表.md) 与 [已支持协议与维护指南](../docs/已支持协议与维护指南.md) 为准。本文只写 iOS 怎么接这些现成能力，不改那些文档。

## 1. 硬边界

以下路径是 Mac 版，iOS 工作不得修改、移动或格式化：

- `HopWorld/`
- `HopWorldShared/`
- `HopWorldTunnel/`
- `HopWorldTunSupervisor/`
- `HopWorldTests/`
- `project.yml` 里现有 Mac Target 的 sources、依赖和签名段
- `Configs/Signing.xcconfig` 里现有的 Mac Bundle ID

`project.yml` 的 Mac 源码根是 `HopWorld/`，不包含本目录。因此本目录里的文档和将来的 iOS 源码不会进 Mac 构建。

将来若要登记 iOS Target，只允许在 `project.yml` **追加** iOS 段。追加时不得改 Mac Target 的源文件列表、Bundle ID、entitlements 或部署版本。

共用解析时，iOS Target 按现有路径引用文件，不把文件搬出 `HopWorld/`，也不把这些文件改成 `public`、抽成 framework 或放进 `HopWorldShared/`。`HopWorldShared/` 现在只有 Mac 隧道状态和 App Group，和节点解析无关。

iOS 需要和 Mac 不同的行为时，写在 `HopWorldIOS/` 里。禁止为了编译 iOS 去改 Mac 文件。

## 2. 首版做什么

手机首版只做四件事：

1. 导入订阅地址或单条分享链接。
2. 按国家或节点选择。
3. 连接和断开。
4. 查看该次延迟。

最低系统为 **iOS 13.0**，与 Mac 的 macOS 13.0 对齐。界面用 iOS 13 就有的 `NavigationView` 做三四屏，不移植 Mac 的 `NavigationSplitView`、侧栏宽度和菜单栏。

明确不做：

| Mac 能力 | iOS |
| --- | --- |
| 菜单栏、Dock、窗口工具栏 | 没有对应物 |
| 系统代理 | iOS 不提供同等接口 |
| 仅指定应用（TUN） | 个人安装的客户端做不到，见第 4 节 |
| 软路由 | 那是 Mac 给局域网里的手机当出口，手机自己不需要再做一遍 |
| Codex / Cursor / Claude 用量、iMessage 重置提醒 | 读的是 Mac 本机登录和钥匙串 |
| 路由策略编辑器、实验室工具、分应用名单 | 不在首版 |
| 把 `AppState`、`ConnectionManager`、`XrayProcessManager` 搬过来 | 这些类型绑着 AppKit 和本机进程 |

按域名、IP 或地理位置分流可以等整机隧道稳定后再加。首版连接意味着当前选中的节点接管本机流量，不提供「只让某几个 App 走代理」的开关。

## 3. 流量怎么接管

Mac 是下载 Xray / sing-box，再用 `Process` 拉起，然后设置系统代理或 TUN。iOS 不允许这样拉起下载来的可执行文件。

iOS 必须用 Network Extension 的 Packet Tunnel：主 App 负责订阅、节点和开关；隧道扩展里跑编进去的代理核心，由系统把整机流量送进扩展。这一步和页面多少无关，只做「连接 / 断开」也要做。

需要付费的 Apple Developer Program。免费 Apple ID 不能使用 Network Extension。签名、App Group 和扩展的 Bundle ID 使用开发者自己的前缀，不要复用别人 fork 里已经登记过的 ID。

`XrayConfigBuilder` 先留在 Mac。它假定本机进程和回环端口。iOS 在选定内嵌核心之后，于 `HopWorldIOS/` 里另写配置生成，不改 Mac 那份。

核心选型和嵌入方式在开工时单独立项。未决定之前不下载内核、不把二进制放进仓库、不改 Mac 的 `XrayInstaller`。

## 4. 不能做指定应用

Mac 的「仅指定应用」是 sing-box TUN 按可执行文件路径匹配：名单内进代理，其余直连。系统能告诉隧道连接来自哪个进程。

iOS 的普通 Packet Tunnel 拿不到「这个包是哪个 App 发出的」。用户不能在跃界里勾选微信、Safari 等只走代理。按应用转发只存在于企业设备管理下发的 Per-App VPN，不属于本客户端。

系统设置里为 Wi-Fi 手填的 HTTP 代理也是整机行为，而且很多 App 不遵守它。那是 Mac 软路由的用法，不是 iOS 版的功能。

## 5. 可以引用、但不能改的 Mac 文件

这些文件当前只依赖 Foundation（地址解析用的 `inet_pton` 在 iOS 上可用）。开工后由 iOS Target **引用原路径**参与编译：

解析：

- `HopWorld/Parsers/ClashYAMLParser.swift`
- `HopWorld/Parsers/VMessParser.swift`
- `HopWorld/Parsers/ShareLinkExporter.swift`
- `HopWorld/Parsers/TrojanParser.swift`
- `HopWorld/Parsers/FinalMaskCodec.swift`
- `HopWorld/Parsers/VLESSParser.swift`
- `HopWorld/Parsers/SubscriptionParser.swift`
- `HopWorld/Parsers/ShadowsocksParser.swift`
- `HopWorld/Parsers/RemoteProtocolParser.swift`
- `HopWorld/Parsers/ShareLinkComponents.swift`

模型与国家名：

- `HopWorld/Models/ProxyNode.swift`
- `HopWorld/Models/Subscription.swift`

协议仍是这 11 种：VLESS、VMess、Trojan、Shadowsocks、Hysteria2、MASQUE、TUIC、AnyTLS、WireGuard、SOCKS5、HTTP。导入成功只表示字段能读出来。某种传输或安全层能否在 iOS 隧道里接通，取决于第 3 节选定的内嵌核心，不能照抄 Mac「已接入」就当成 iOS 已验收。

下列文件留在 Mac，不加入 iOS Target：`ApplicationProxy`、应用选择、Codex / 健康检查 / 分应用策略、`ConnectionState`、`AppState`，以及 `HopWorld/Views/`、`HopWorld/Services/Xray/`、`HopWorld/Services/System/`、`HopWorld/Services/ApplicationProxy/`。

## 6. 工程标识

| 项目 | Mac（已有，不要改） | iOS（提议，开工时再写进配置） |
| --- | --- | --- |
| 显示名 | 跃界 | 跃界 |
| 最低系统 | macOS 13.0 | iOS 13.0 |
| Target | `HopWorld` | `HopWorldIOS`，外加一个 Packet Tunnel 扩展 |
| Bundle ID | `com.hopworld.app` | `com.hopworld.ios` |
| 扩展 Bundle ID | `com.hopworld.app.PacketTunnel` | `com.hopworld.ios.PacketTunnel` |
| App Group | `group.com.hopworld.app` | `group.com.hopworld.ios` |

本地若用 `Configs/Signing.local.xcconfig` 换了前缀，iOS 跟着换前缀，仍然不要和 Mac 的 Bundle ID、App Group 用同一个。两套 ID 不能混用，否则隧道配置和钥匙串会串到 Mac。

## 7. 目录

```text
HopWorld/                      Mac 应用，不动
HopWorldShared/                Mac 隧道共享，不动
HopWorldTunnel/                Mac Packet Tunnel，不动
HopWorldTunSupervisor/         Mac TUN 辅助进程，不动
HopWorldIOS/                   只有 iOS
    开发文档.md                 本文件
    App/                       开工后：订阅、国家、连接界面
    Tunnel/                    开工后：Packet Tunnel 扩展
project.yml                    现在不改；开工时只追加 iOS Target
```

`App/` 和 `Tunnel/` 在真正写代码时再建。现在不建空目录，也不生成 Xcode 工程。

## 8. 开工顺序

1. 确认付费开发者账号、Bundle ID 前缀和 Network Extension 权限。
2. 选定内嵌核心，并在 `HopWorldIOS/Tunnel/` 证明一条节点能完成一次往返。此步不要改 Mac 的安装器和进程管理。
3. 在 `project.yml` 追加 iOS App 与扩展。`IPHONEOS_DEPLOYMENT_TARGET` 设为 `13.0`。源码只来自 `HopWorldIOS/`，再加上第 5 节的原路径引用。Mac 的 `MACOSX_DEPLOYMENT_TARGET` 保持 `13.0`，不要改成别的值。
4. 做导入、国家或节点列表、连接和断开、延迟。订阅解析直接调用现有解析器。
5. 用一条真实订阅在真机上走完：导入、选择、连接、打开网页、断开后流量不再进隧道。

Mac 方案 `xcodebuild -project HopWorld.xcodeproj -scheme HopWorld` 应保持可用。iOS 使用单独的 scheme，不替换 Mac scheme。

## 9. 验收

- 本目录的增加不改变 Mac 的编译输入。
- iOS 首版四项功能在真机隧道里可用。
- 没有「指定应用」开关，也没有把 Mac 的分应用配置移植过来。
- `HopWorld/` 与第 1 节列出的其他 Mac 路径，相对开工前没有为 iOS 产生的差异。
