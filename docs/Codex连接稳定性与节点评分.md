# Codex 连接稳定性与节点评分

> 2026-10-27 入口更新：本文保留早期参考评分设计与验收记录。节点详情中的旧评分区已移除；现从主窗口顶部连接状态前方的节点评分数值入口打开网络健康中心查看。公开 HTTPS / WebSocket / UDP 结果位于「节点」，真实应用状态与评分分别位于「应用」「评分」，两者证据分开。下文旧版“评分场景”入口不再适用。

日期：2026-10-24。适用 HopWorld 的系统代理、全局 TUN、分应用 TUN。

## 本次实现

- 两种 TUN 使用同一 IPv4/IPv6 接口和同一组分流规则。Xray 目标 DNS 使用 `UseIP`，节点拨号使用 `UseIPv4v6`，保留 IPv4 优先及 IPv6-only 节点解析能力。实际双栈可达性仍取决于本机网络和节点。
- 全局 TUN 使用 `dns_mode=hijack`，TCP/UDP 53 通过当前节点访问远程 DNS。只给节点域名保留直连引导解析，避免 DNS → 代理 → DNS 回环；核心和 HopWorld 的防回环直连继续生效。
- macOS 的系统解析器由进程共享；分应用模式使用 `dns_mode=disabled`，TCP/UDP 53 优先直连，不设置代理 DNS，避免节点故障使未选中应用也无法解析。该模式的系统 DNS 使用本地出口，不承诺 DNS 与应用代理出口一致。应用自己发起的 DoH/DoT 属于普通加密连接，跟随该应用的流量规则；系统代理模式不接管 macOS 系统 DNS。
- Xray 内部 DNS 用专用 tag 匹配路由：远程解析经代理，直连模式和国内分流解析走直连。移除普通查询的 `localhost` 回退，避免远程解析失败时静默走本机 DNS；节点引导仍独立走系统解析。
- Xray 的连接空闲上限从默认 300 秒延长为 3600 秒。TCP 节点配置 30 秒空闲后开始保活，间隔 15 秒；TUN 到本地 SOCKS 的 TCP 链路同样设置保活。没有启用连接复用，也没有为了降低延迟而周期切换节点。TCP 443 按普通 TCP 连接转发，可承载 WebSocket Upgrade 和加密数据。
- 没有安装根证书、TLS 终止入站或 MITM。TLS 解密保持关闭。用于路由的 TLS ClientHello 嗅探设置 `routeOnly=true`，不据此改写连接目标；代理节点自身的 TLS 仍正常验证。
- 早期节点详情曾提供 Codex / Claude「评分场景」切换（该入口现已移除），显示对应的节点质量基础观测。沿用现有的约 5 秒一次 HTTPS 探测，保留本次应用运行内最近 120 次请求；至少 10 次请求后显示通用网络基础分。探测目标来自设置中的测试地址，不能当成 Codex 登录、真实会话或 WebSocket 验证。两种场景共用基础样本，Claude 专项定义见 [Claude 连接稳定性与节点评分](Claude连接稳定性与节点评分.md)。
- 每 12 次探测补查一次出口 IP；同一节点的有效观测变化单独计数，缺失结果不计变化。手动换节点使用不同节点记录。重新连接同一节点后的出口变化仍计数，但不单凭此归因故障。节点连接参数、测试地址或接管/路由模式改变时重置该节点观测。
- 日志包含诊断 session、异常断开时长、HTTPS 连续失败/恢复、HTTP 状态/错误原因、核心错误尾部和出口变化。URL、认证头、Cookie、结构化密码/令牌、UUID 和 IPv4/IPv6 字面量在进入日志和导出时脱敏。IP 使用每次启动随机密钥的 HMAC 标识，支持单次运行内关联；日志文件原子写入且权限为 0600。旧日志加载和导出也再次脱敏。

这些调整控制本地行为，不能延长节点、CDN、NAT 或远端应用设置的超时，也不能凭 HTTP 探测解释真实 Codex WebSocket 的关闭原因。

## 评分设计（100 分）

各维度先转换为 0～1 的质量值，再乘权重相加。公式属于产品初始阈值，需通过实测校准。未知项显示“未观测”，不赋满分、不重新归一化到 100 分。

| 维度 | 权重 | 取值及初始公式 | 当前证据 |
| --- | ---: | --- | --- |
| 长连接稳定性 | 35 | 同一路径上完成规定观测时长的 WSS 会话数 / 有效 WSS 会话数 | 可主动运行 360 秒公开 WSS 参考链路观测，不用 TUN 在线时长代替 |
| 丢包 | 15 | `max(0, 1 - loss / 0.05)`；0% 得满分，≥5% 得 0 分 | 可主动运行 STUN UDP 往返缺失测量；HTTPS 失败率不是丢包率 |
| 延迟抖动 | 15 | `max(0, 1 - jitterMs / 300)` | 相邻成功 HTTPS 请求总耗时差的绝对值均值；失败会断开相邻序列 |
| 请求成功率 | 20 | 有效成功 HTTPS 请求数 / 已完成请求数 | 成功标准沿用测试目标的 HTTP 策略；取消的请求不入样本 |
| 网络延迟 | 15 | `clamp(1 - max(0, P95ms - 200) / 1800, 0, 1)` | 成功 HTTPS 请求总耗时的 P95，包含建连/TLS/响应，非纯 TCP RTT |

未运行专项时，基础观测最多显示“50 / 50（覆盖 50%）”。现已提供 [WebSocket 与 UDP 专项实测](WebSocket与UDP专项实测.md)：有效参考 WSS 观测增加 35% 覆盖，有效 UDP 观测增加 15%；验证失败、取消未完成或过期的项目不补分。100% 覆盖仍只说明本轮参考链路证据齐全，不证明真实 Codex 会话或服务商永久稳定。全部 HTTPS 请求失败且没有专项数据时，仅覆盖成功率 20 分。评分不接入自动优选。

出口变化、TCP 重传、并发限制及跨时段退化作为证据标签，不重复计入基础分。完整排名至少要求相同目标、相同时长与并发、两种 IP 协议的覆盖说明、足够样本和新鲜度；不把不同覆盖度的分数直接排序。

## 需要专项采集的证据与归因

| 疑点 | 验证方法 | 能得出的结论与限制 |
| --- | --- | --- |
| 出口 IP 频繁变化 | 保持同一节点、同一网络；连续采样出口，记录时间、IP 协议、session 和网络变化事件 | 只能确认观测到出口变化。第三方出口检测与 Codex 的目的地址可能被服务商分流到不同出口；不能等同 Codex 会话出口变化 |
| 长连接超时 | 对自有或明确允许的 WSS 443 端点，经与 Codex 相同接管路径测试；分别观测 5/15/30 分钟空闲和端点允许的心跳场景 | 记录 Upgrade/TLS 结果、ping/pong RTT、close code、EOF/reset、持续时长与客户端取消。测试端点失败不能直接证明 Codex 服务故障；真实应用日志需单独授权读取 |
| TCP 重传率较高 | 针对本机到节点的具体 TCP socket 采集 `TCP_CONNECTION_INFO` 等受支持统计，取同一连接的发送/重传计数差值 | 不能拿全机 `netstat` 累积量当该节点指标；节点到目标段通常不可见。Hysteria2 等 QUIC 链路需独立 QUIC 遥测，不能给 TCP 指标填 0 |
| 真正的丢包 | 使用允许的 UDP 回显/序列号测试，分别覆盖 IPv4/IPv6；记录发送数、收到数、重复和乱序 | ICMP 可能不被 SOCKS/TUN 链路承载。应用请求失败、TCP 重传、ICMP 丢弃不可混为一项 |
| 并发连接限制 | 固定节点/端点，在用户主动开始的专项测试中逐级测试 1/4/8/16 并发；每档固定时长，并记录成功率与尾延迟 | 并发升高后退化只标“疑似限制/拥堵”；对照本地资源、目标限流（429）、另一节点后再判断。达到失败阈值立即停止升档 |
| 特定时段重启 | 经用户启用后跨至少 3 天记录连接失败时间、网络状态、核心退出、多个目标和节点的同步失败 | 只有多日重复窗口且本地网络/核心正常时才提示“疑似服务商周期中断”。服务商日志或公告才可进一步确认重启 |
| 同出口用户过多导致拥堵 | 同节点在高峰/低峰固定目标比较 P95、吞吐、抖动及重传，并和另一出口对照 | 本地无法得知出口共享人数。可标“高峰退化”，不能断言“共享用户过多”；Wi-Fi、运营商和目标服务器也可能造成拥堵 |

专项测试不得发送账号 token、对话内容或订阅凭证到测试端点。TLS 校验失败保留失败原因，不开启跳过证书校验。故障诊断先记录现象，再提出候选原因，最后用对照试验缩小范围。

## 验收边界

专项更新：见 [实际观测入口、测量边界与验证](WebSocket与UDP专项实测.md)。

自动检查覆盖：评分边界/缺失数据/窗口、失败样本、出口变化去重、敏感日志/历史导出/文件权限、双栈配置、DNS 出站规则、TLS 透传及长连接配置。真实核心执行配置检查和无 TUN 的服务初始化，核对字段兼容性。

本次验证：Debug 应用与测试构建通过。完整测试运行 228 项，225 通过、1 项管理员 TUN 测试跳过、2 项原有加密库测试失败（`testDamagedPrimaryRestoresWholePreviousCommitAndRetainsDamagedFile`、`testMigrationEncryptsAllSecretsAndRemovesLegacyOnlyAfterSuccessfulCommit`）。失败点为 `SecureLibraryStore.load()` 的已有逻辑在读取加密文件时使用真实钥匙串候选密钥而非测试注入的 `keyProvider`；本次未改动加密库。Xray 各路由模式/协议配置检查及 sing-box 1.14.2 的两种 TUN 配置检查、无权限 DNS/出站初始化均通过。

macOS TCC 可能禁止测试子进程读取“文档”目录中的核心/规则资源。可先将 `xray`、`geoip.dat`、`geosite.dat` 暂存于测试目录，用 `HOPWORLD_TEST_XRAY` 指向暂存的 Xray；`HOPWORLD_TEST_SING_BOX` 指向已有的 1.14.2 核心。将变量传给实际 `xctest` 进程；仅在启动 `xcodebuild` 的 shell 设置变量不一定传递到测试进程。检查过程不启用 TUN，不改变系统路由/DNS。

仍需本机管理员 TUN 实测：IPv4/IPv6 分别访问同一允许的目标，检查系统 DNS 与节点出站，断开后路由/DNS 恢复，以及持续超过 300 秒的 WSS 连接和跨时段表现。构建或核心配置检查通过不能代替这些验收。未读取用户的 Codex 会话日志，未进行真实节点性能归因。
