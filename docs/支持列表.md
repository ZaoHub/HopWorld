# 支持列表

最后核对：**2026-11-06**。范围是当前工作区源码。已安装的 App、旧安装包和另一套内核版本可能不同。

这里只列当前能导入并接入连接的能力，以及明确不支持的边界。内核自己支持某项能力，不表示 HopWorld 已经接入。解析成功也不等于每种传输、安全层和公网节点都验收过。

怎么改这份列表、补测试和核对内核，见 [已支持协议与维护指南](已支持协议与维护指南.md)。MASQUE、TUIC、WireGuard、SOCKS5、HTTP 的字段示例见各自专项文档。

## 节点协议

共 **11** 种。HTTP 与 HTTPS CONNECT 共用 `http`。TLS、REALITY 是安全层，不单独算一种协议。

| 协议 | 导入 | 内核 | 已接入 | 未接入 |
| --- | --- | --- | --- | --- |
| VLESS | `vless://`，YAML `vless` | 通常 Xray。公网无 TLS，或旧 H2/HTTP，转 sing-box | UUID，`encryption=none`。TCP、WebSocket、gRPC、HTTPUpgrade、XHTTP、旧 H2/HTTP。REALITY、FinalMask（Xray 路径） | sing-box 桥接拒绝 FinalMask，也拒绝 VLESS Encryption。公网明文 VLESS 不能同时用 FinalMask |
| VMess | `vmess://` Base64 JSON，YAML `vmess` | 通常 Xray。旧 H2/HTTP 转 sing-box | UUID，加密默认 `auto`。`aid`、`scy`、`net`、`tls`。XHTTP 与 `splithttp`。REALITY 公钥、短 ID、SpiderX | 旧 H2/HTTP 上非默认 SpiderX 无法保留 |
| Trojan | `trojan://`，YAML `trojan` | 通常 Xray。旧 H2/HTTP 转 sing-box | 密码，默认 TLS。SNI、Host、Path、gRPC 服务名。REALITY 公钥、短 ID、SpiderX | 旧 H2/HTTP 上非默认 SpiderX 无法保留 |
| Shadowsocks | `ss://`（SIP002 与旧式 Base64），YAML `ss`、`shadowsocks` | 现代加密走 Xray。`rc4-md5` 与 AES-CFB 走 sing-box | 下方加密白名单 | SIP003 插件。旧加密不接受额外传输、TLS、REALITY、FinalMask |
| Hysteria2 | `hysteria2://`、`hy2://`，YAML `hysteria2`、`hy2`。导出统一为 `hysteria2://` | 通常 Xray `hysteria` 版本 2。`insecure=1` 且没有证书固定摘要时转 sing-box | 密码、TLS，缺端口时默认 443。SNI、ALPN、`insecure`、`pinSHA256` | 混淆、多端口 |
| MASQUE | `masque://`，YAML `masque`。这是 HopWorld 的导入约定 | Xray 26.10.21 或更新 | 标准 CONNECT-IP，H3/H2。Basic 或请求头认证，必须验证证书。默认 H3、端口 443 | 跳过证书验证。Cloudflare WARP 设备注册和专用密钥 |
| TUIC | `tuic://`，YAML `tuic` | sing-box | v5 的 UUID、密码、TLS。TCP/UDP，默认 443 | v4 token |
| AnyTLS | `anytls://密码@主机:端口`，YAML `anytls` | sing-box | 密码、TLS/TCP，默认 443 并验证证书。UDP 经 UoT。SNI、`insecure`、指纹、ALPN | 额外传输、FinalMask、ECH、证书固定摘要、自定义会话池、REALITY |
| WireGuard | `wireguard://`、`wg://`，或单 Peer 标准配置。YAML `wireguard` | Xray 用户态，`noKernelTun=true` | 单 Peer。私钥、本地地址、Peer 公钥、预共享密钥、AllowedIPs、Reserved、MTU、Keepalive、DNS。默认 51820 | 多 Peer，配置钩子 |
| SOCKS5 | `socks5://`、`socks://`，YAML `socks5` | Xray | 匿名或用户名密码。TCP 与标准 UDP relay，默认 1080 | SOCKS4/4a，TLS 或 WebSocket 包装 |
| HTTP | `http://`、`https://`，YAML `http`（`tls: true` 为 HTTPS） | Xray | HTTP/1.1 CONNECT，仅 TCP。匿名、Basic 或 CONNECT 请求头。默认 80/443。HTTPS 必须验证证书，可固定证书摘要 | UDP |

这 11 种都能导出分享链接，并进入现有节点测试和连接。导出受字段映射限制，不能保证任意上游链接无损往返。

系统代理、规则代理、全量 TUN、分应用 TUN 是流量接管方式，不是节点协议。本地 HTTP/SOCKS 入口和远程 HTTP/SOCKS 节点是两套用途。

## 传输

| 传输 | 行为 |
| --- | --- |
| TCP | 原生 TCP |
| WebSocket | 保留 Path。Host 缺省时按 SNI、节点地址补选 |
| gRPC | 保留服务名。服务名可以为空，是否匹配由服务端决定 |
| HTTPUpgrade | 保留 Host、Path |
| XHTTP | VLESS 链接、VMess JSON 和 Clash YAML 里的 `splithttp` 也按 XHTTP 识别。YAML 保留 `xhttp-opts` 的 Host 和 Path。`mode`、`extra` 没有接入，使用内核默认值 |
| 旧 H2、HTTP | VLESS、VMess、Trojan 交给 sing-box 的 HTTP 传输。保留 Host 列表和 Path。有 TLS 时为 H2，无 TLS 时为 HTTP/1.1 |
| 旧 QUIC | 当前按 XHTTP 生成，不保证能连上旧 QUIC 服务端 |
| Hysteria2、TUIC、WireGuard、MASQUE、AnyTLS | 使用各自的原生传输。节点模型里默认的 `transport=tcp` 不代表外层一定是 TCP |

各导入入口并不完全相同：

- VLESS 分享链接识别 TCP、WebSocket、gRPC、HTTPUpgrade、XHTTP/SplitHTTP，以及旧 H2、HTTP、QUIC 名称。
- VMess JSON 识别 WebSocket、gRPC、HTTPUpgrade、XHTTP/SplitHTTP，以及旧 H2、HTTP、QUIC。
- Trojan 分享链接识别 WebSocket、gRPC、HTTPUpgrade、XHTTP、旧 H2、HTTP。其他值落入 TCP。
- VLESS、VMess 分享链接里无法识别的传输名称也会落入 TCP。Clash YAML 遇到未知网络类型则拒绝解析。落入 TCP 不等于该传输已经实现。

## 安全层

普通 TLS 用于需要 TLS 的协议，可带 SNI、ALPN 和指纹。REALITY 只接在 VLESS、VMess、Trojan 上。

| 项目 | VLESS / VMess / Trojan |
| --- | --- |
| 分享链接 | `pbk` 非空就按 REALITY 处理，即使写成 `security=tls`。`sid`、`fp`、`spx` 分别是短 ID、指纹、SpiderX。也接受 `publicKey`、`shortId` 等常见别名 |
| Clash YAML | `reality-opts.public-key`、`reality-opts.short-id` 和 `reality-opts.spider-x` 对 VLESS、VMess、Trojan 都保留 |
| Xray 路径 | TCP、WebSocket、gRPC、HTTPUpgrade、XHTTP 写出 `realitySettings`，含公钥、短 ID、SpiderX |
| 旧 H2/HTTP | 走 sing-box。保留公钥和短 ID。没有指纹时 uTLS 使用 `chrome`。SpiderX 只允许空或 `/`，其他值拒绝。FinalMask 和证书 SHA-256 固定摘要也拒绝 |
| 缺少公钥 | 判为配置失败，不猜测公钥，也不改成普通 TLS |

其他安全限制：

- AnyTLS 拒绝 REALITY。
- Shadowsocks 旧加密拒绝 TLS 和 REALITY。
- FinalMask（分享链接 `fm`）已接入 VLESS、VMess、Trojan 的 Xray 路径。sing-box 桥接拒绝 FinalMask。不能据此认为所有 YAML 入口都保留该字段。
- VLESS 的 `flow` 和 `encryption` 会进入配置，具体组合仍由内核校验。

## Shadowsocks 加密

以下是当前允许的名称，不是上游内核的全部算法。

| 路径 | 允许的加密 |
| --- | --- |
| Xray AEAD | `aes-128-gcm`、`aes-256-gcm`、`chacha20-ietf-poly1305`、`chacha20-poly1305`、`xchacha20-ietf-poly1305`、`xchacha20-poly1305` |
| Xray SS2022 | `2022-blake3-aes-128-gcm`、`2022-blake3-aes-256-gcm`、`2022-blake3-chacha20-poly1305` |
| sing-box 旧加密 | `rc4-md5`、`aes-128-cfb`、`aes-192-cfb`、`aes-256-cfb`。仅 `transport=tcp`、`security=none` |

其他算法会报不支持，包括尚未单独接入的 CTR 类算法。旧加密没有现代 AEAD 完整性保护，只为兼容保留。

带 SIP003 `plugin` 的链接可能导入出基础节点并忽略插件。导入成功不等于插件已生效。

## 订阅与分享格式

支持单条分享链接、按行文本、可识别的粘连链接、Base64 分享链接订阅，以及 `proxies:` YAML 子集。

YAML 支持块列表、无缩进列表、行内列表、嵌套映射、常见 ALPN 与 H2 Host 列表、普通字符串续行，以及引号内的标点。不支持锚点、别名和 `|`、`>` 块标量。它不是通用 YAML，也不是完整 Clash 配置导入器。

补充约定：

- WireGuard 可导入单 Peer 标准配置，保存时规范成 URI。
- HTTP 代理从节点分享链接入口导入，并且要显式带端口。带网站或订阅路径的 HTTP URL 不会被当成节点。订阅 URL 入口仍会下载订阅。
- Hysteria2 YAML 的 `fingerprint` 是证书固定摘要，不是 TLS 客户端指纹。
- MASQUE 的 `masque://` 和 YAML 字段是 HopWorld 的约定。未知或重复参数会拒绝解析。

## 明确未接入

ShadowsocksR、Hysteria 1、NaiveProxy、SOCKS4/4a、TUIC v4，以及 Cloudflare WARP 的 MASQUE 专用配置，都不能作为节点导入。
