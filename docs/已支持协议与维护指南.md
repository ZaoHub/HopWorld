# 已支持协议与维护指南

最后核对：**2026-10-28**。范围为当前工作区源码；已安装 App、历史压缩包及不同内核版本可能与源码不同，发布前需单独核对。

本文件是协议能力总表和维护入口。新增协议、修改解析规则、切换内核或改变测试流程时应同步更新。专项参数与示例见 [MASQUE 隧道协议](MASQUE隧道协议.md)、[TUIC、WireGuard、SOCKS5 与 HTTP 节点](TUIC-WireGuard-SOCKS5-HTTP.md)。

## 1. 支持口径

维护时分别记录以下层次，不能相互替代：

| 层次 | 含义 |
| --- | --- |
| 解析支持 | 可从链接或订阅读出字段；不代表所有参数都被保留 |
| 配置与连接接入 | 能选择内核、生成配置，并进入现有测试及连接流程 |
| 本地实测 | 使用真实内核和本地服务完成数据往返 |
| 公网及系统接管验收 | 使用实际节点验证网络环境、系统代理或 TUN 接管及清理 |

本地配置校验、构建成功和单次公网测试，都不能单独证明长期稳定性或全部协议组合可用。上游内核支持某项能力，也不表示 HopWorld 已接入。

## 2. 节点协议总表

当前 `ProxyProtocolType` 共 **11 种**。HTTP 与 HTTPS CONNECT 共用 `http` 类型，各行的限制是当前客户端实现的边界。

| 协议 | 分享链接 | `proxies:` YAML 类型 | 默认凭证/安全设置 | 使用内核与限制 |
| --- | --- | --- | --- | --- |
| VLESS | `vless://` | `vless` | UUID；`encryption=none`、`security=none` | 通常使用 Xray。公网无 TLS 或旧 H2/HTTP 传输转 sing-box；该桥接只接受 `encryption=none`，支持 TCP、WS、gRPC、HTTPUpgrade、旧 H2/HTTP，拒绝 FinalMask |
| VMess | `vmess://`，Base64 JSON | `vmess` | UUID；加密默认 `auto` | 通常使用 Xray；旧 H2/HTTP 使用 sing-box。支持解析 `aid`、`scy`、`net`、`tls` 等字段。VMess REALITY 未接入 |
| Trojan | `trojan://` | `trojan` | 密码；TLS 默认开启 | 通常使用 Xray；旧 H2/HTTP 使用 sing-box。支持 SNI、Host、Path、gRPC 服务名等。当前分享链接解析器没有完整接入 Trojan REALITY 凭证 |
| Shadowsocks | `ss://`，含 SIP002 用户信息及旧式 Base64 形式 | `ss`、`shadowsocks` | 加密方式与密码 | 现代加密使用 Xray；原生 `rc4-md5`、AES-CFB 通过 sing-box 桥接，见加密表。没有接入 SIP003 插件 |
| Hysteria2 | `hysteria2://`、`hy2://`；导出统一为 `hysteria2://` | `hysteria2`、`hy2` | 密码；TLS；链接未带端口时默认 443 | 通常使用 Xray 的 `hysteria` 出站，版本为 2；`insecure=1` 且无证书固定摘要时转 sing-box。混淆和多端口选项未接入 |
| MASQUE | `masque://`，HopWorld 自定义导入约定 | `masque`，HopWorld 支持的 YAML 形式 | Basic 或请求头认证；必须 TLS；默认 H3、端口 443 | 使用 Xray 26.10.21+；标准 CONNECT-IP，支持 H3/H2。拒绝跳过证书验证；不包含 WARP 设备注册及专用密钥配置 |
| TUIC | `tuic://` | `tuic` | v5 UUID/密码、TLS；默认 443 | sing-box 桥接，支持 TCP/UDP；不支持 v4 token。拥塞控制、UDP 模式、证书信任等选项见专项文档 |
| AnyTLS | `anytls://password@host:port` | `anytls` | 密码、TLS；默认 443，默认验证证书 | sing-box 桥接，原生 TLS/TCP，UDP 经 UoT。保留 SNI、`insecure`、`fp`、ALPN；拒绝额外传输、FinalMask、ECH、证书固定摘要和自定义会话池参数 |
| WireGuard | `wireguard://`、`wg://`，或标准客户端配置 | `wireguard` | 客户端私钥、本地地址、Peer 公钥；默认 51820 | Xray 用户态出站，TCP/UDP；仅单 Peer。私钥、预共享密钥、AllowedIPs、Reserved、MTU、Keepalive、DNS 已接入；不执行配置钩子 |
| SOCKS5 | `socks5://`、`socks://` | `socks5` | 匿名或用户名密码；默认 1080 | Xray 远程 SOCKS5 出站，支持 TCP、标准 UDP relay；无 SOCKS4/4a、TLS/WS 包装 |
| HTTP | `http://`、`https://` | `http`，`tls: true` 表示 HTTPS | 匿名、Basic 或 CONNECT 请求头；默认 80/443 | Xray 远程 HTTP/1.1 CONNECT，仅 TCP；HTTPS 必须验证证书，可固定证书摘要 |

十一种协议均接入分享链接导出、节点测试和现有连接入口。导出受当前字段映射限制，不能据此承诺任意上游链接都能无损往返；新增字段时必须补往返测试。

`HTTP`、`SOCKS` 同时用作本地入口/内部桥接和远程节点；维护时应分别核对。系统代理、规则代理、全量 TUN、分应用 TUN 属于流量接管方式；TLS、REALITY 属于安全层，均不单独计入节点协议数量。

## 3. 内核分工与版本

| 项目 | 当前源码设置 | 维护位置 |
| --- | --- | --- |
| Xray 默认安装版本 | `26.10.21` | `XrayInstaller.preferredVersion`、`Scripts/fetch_xray.sh` |
| MASQUE 客户端要求 | Xray `26.10.21` 或更新版本 | `XrayInstaller.masqueMinimumVersion`、`XrayProcessManager.start` |
| sing-box 桥接版本 | `1.14.2` 基线；已适配更新版 `1.14.4`，按架构固定归档 SHA-256 | `SingBoxInstaller.version` / `approvedVersion` |
| 独立 GeoFiles | Loyalsoldier 同一发布日期的 `geoip.dat` / `geosite.dat`；摘要与本地 Xray 校验后成套切换 | `GeoFilesInstaller`、`ComponentUpdateManager` |

内核选择不只取决于协议名称：

1. `SingBoxConnectionConfig.requiresSingBox` 判断是否需要协议桥接。
2. `XrayConfigBuilder` 生成 Xray 出站或带桥接标记的本地 SOCKS 出站。
3. `SingBoxConnectionBridge` 建立带随机认证的回环入口，再启动对应的 sing-box 出站；路由与统计仍沿用现有 Xray 链路。
4. `XrayProcessManager` 管理进程启动、退出及桥接清理；MASQUE 会在启动前检查内核版本。

TUIC、AnyTLS 始终交给 sing-box 协议桥接。WireGuard 使用 Xray 用户态协议实现，并设置 `noKernelTun=true`；这不代表关闭 HopWorld 另行选择的全量/分应用 TUN 接管。

已经由用户选定的托管 Xray 版本不一定会被默认版本自动替换。不能只更新默认版本常量就认为所有现存安装都已升级；MASQUE 使用旧内核时应显示升级提示。

在「关于 → 组件更新」可以分别检查 Xray、sing-box 和 GeoFiles，并持久化各自的自动更新开关。后台每天首次启动检查一次；sing-box 只允许应用内固定摘要的已适配版本，未知上游版本需先适配应用。独立规则优先于 Xray 随附资源，Xray 升级时会同时检查随附规则及当前独立规则的兼容性。

升级 sing-box 时须同时核对版本、架构、归档摘要、配置字段及本地往返测试。不要为了兼容节点而跳过下载校验、取消 TLS 校验或自动降级内核。

## 4. 传输方式与安全层

### 4.1 传输映射

| 模型/输入 | Xray 配置行为 | 维护注意 |
| --- | --- | --- |
| `tcp` | `network=tcp` | 原生 TCP |
| `ws` | `wsSettings` | Host 缺省时，配置生成器按 SNI、节点地址补选；使用当前核心的顶层 `host` 字段 |
| `grpc` | `grpcSettings` | `serviceName` 可以为空；是否匹配由服务端决定，不能在本地直接判为缺字段失败 |
| `httpupgrade` | `httpupgradeSettings` | 保留 Host、Path |
| `xhttp` | `xhttpSettings` | VLESS 链接还将 `splithttp` 识别为 XHTTP |
| 旧 `h2`、`http` | VLESS、VMess、Trojan 使用 sing-box `transport.type=http` | 保留 Host 列表、Path；TLS 时为 H2，无 TLS 时按 sing-box 使用 HTTP/1.1；不转换为 XHTTP |
| 旧 `quic` | 当前生成 `network=xhttp` | 不保证能连接旧 QUIC 服务端 |
| `masque` | `masqueSettings` | 仅允许 MASQUE 节点使用；TLS ALPN 决定 H2/H3 |
| Hysteria2 原生传输 | 单独生成 `network=hysteria`、版本 2 | 实际走 UDP，不应由节点模型里默认的 `transport=tcp` 推断其网络方式 |
| TUIC 原生传输 | sing-box `type=tuic` | 实际走 QUIC/UDP，模型默认 `transport=tcp` 不代表实际外层链路 |
| AnyTLS 原生传输 | sing-box `type=anytls`，启用 TLS | 外层走 TCP；UDP 负载通过 UoT 承载，不跳过 TCP 预检 |
| WireGuard 原生传输 | Xray `protocol=wireguard` | 实际走 UDP，自带加密，不使用额外 TLS 安全层 |

各导入入口的映射并不完全相同：

- VLESS 分享链接识别 TCP、WS、gRPC、HTTPUpgrade、XHTTP/SplitHTTP 及旧 H2/HTTP/QUIC 名称。
- VMess JSON 识别 WS、gRPC、HTTPUpgrade 及旧 H2/HTTP/QUIC；目前 `net=xhttp` 未显式接入该解析器。
- Trojan 分享链接识别 WS、gRPC、HTTPUpgrade、XHTTP、旧 H2/HTTP，其他值当前落入 TCP。
- VLESS、VMess 分享链接的未知传输值当前也会落入 TCP；Clash YAML 的未知网络类型则拒绝解析。不能把这种回退当成该传输已实现。
- sing-box 的 VLESS 桥接支持表 2 中列出的传输；XHTTP 等不会自动转换为其他传输。旧 H2/HTTP 支持普通 TLS、SNI、ALPN、uTLS 指纹，明确拒绝 REALITY、FinalMask 及当前版本无法等价保留的证书 SHA-256 固定摘要。

### 4.2 安全及特殊参数

- VLESS 链接的 `pbk` 非空时按 REALITY 处理；`sid`、`fp`、`spx` 分别映射短 ID、指纹和 SpiderX。REALITY 缺少公钥时仍应判为配置失败，不能猜测公钥或自动改成 TLS。
- `flow` 与 VLESS `encryption` 会进入配置，但具体组合仍由所选内核校验；不承诺支持任意上游扩展。
- Hysteria2 支持 `sni`、`alpn`、`insecure`/`allowInsecure`、`pinSHA256`。分享链接拒绝 `obfs`、`obfs-password`、`mport`；YAML 拒绝 `obfs`、`obfs-password`、`ports`。
- AnyTLS 分享链接支持 `sni`、`insecure`/`allowInsecure`、`fp`、`alpn`，允许兼容字段 `security=tls&type=tcp&headerType=none`；YAML 对应 `sni`/`servername`、`skip-cert-verify`、`client-fingerprint`、`alpn`。仅显式 `insecure=1/true` 时跳过证书验证；未知参数拒绝导入，会话池使用核心默认值。密码、TLS 配置、指纹参与去重，日志及去凭证备份会脱敏。
- MASQUE 支持 ALPN、SNI、Host、Path、认证头、隧道 DNS 和证书固定摘要；默认 H3，仅含 H2 时用 H2，同时含 H2/H3 时用 H3。详细字段以专项文档和 `MasqueParser` 为准。
- 分享链接中的 FinalMask `fm` 已在 VLESS、VMess、Trojan 路径接入；不能推定所有 YAML 或其他协议入口也会保留该字段。sing-box 协议桥接目前明确拒绝 FinalMask。

## 5. Shadowsocks 加密白名单

以下是 **HopWorld 当前校验器允许的名称**，不是所有上游内核算法的全集。

| 内核路径 | 允许的加密名称 |
| --- | --- |
| Xray AEAD | `aes-128-gcm`、`aes-256-gcm`、`chacha20-ietf-poly1305`、`chacha20-poly1305`、`xchacha20-ietf-poly1305`、`xchacha20-poly1305` |
| Xray SS2022 | `2022-blake3-aes-128-gcm`、`2022-blake3-aes-256-gcm`、`2022-blake3-chacha20-poly1305` |
| sing-box 兼容桥接 | `rc4-md5`、`aes-128-cfb`、`aes-192-cfb`、`aes-256-cfb` |

旧加密桥接仅允许原生 Shadowsocks：`transport=tcp`、`security=none`，不接受额外传输、TLS/REALITY 或 FinalMask。这些旧算法的兼容不改善其安全性，建议服务端迁移到现代加密。

其他算法仍会报不支持，包括没有单独接入的 CTR 类算法。即使 sing-box 自身支持更多算法，也不能直接扩大客户端白名单而不补桥接选择、配置与测试。

含 SIP003 `plugin` 的 Shadowsocks 链接没有完整支持；现有解析器可能保留基础节点而忽略附加信息，不能把“导入成功”当成插件已生效。

## 6. 订阅与导出格式

支持直接分享链接、按行文本、可识别的粘连链接、Base64 分享链接订阅，以及 `proxies:` YAML 子集。

WireGuard 额外支持单 Peer 标准配置；在分享链接订阅中规范化为 URI 保存。HTTP 代理从“节点分享链接”入口导入并显式提供端口；带网站/订阅路径的 HTTP URL 不作为节点提取，“订阅 URL”入口仍执行订阅下载。

YAML 支持块列表、无缩进列表、行内列表、嵌套映射、常用 ALPN/H2 Host 列表、普通字符串续行及引号内标点；不支持锚点、别名、`|`/`>` 块标量等完整 YAML 语法。它不是通用 YAML 或完整 Clash 配置导入器。

维护字段时应同时核对：分享链接输入、YAML 输入、导出、节点库编码、订阅合并与指纹。尤其注意：

- REALITY 的分享链接公钥入口是 `pbk`，YAML 常用 `reality-opts.public-key`，不能只核对其中一个入口。
- Hysteria2 YAML 的 `fingerprint` 当前用于证书固定摘要，不是 TLS 客户端指纹字段。
- MASQUE 的 `masque://` 及 YAML 字段属于 HopWorld 导入约定，不代表其他客户端采用相同格式；未知或重复的 MASQUE 链接参数会拒绝解析。
- 新增协议后，必须更新链接提取正则，否则“单条可解析、订阅批量提取不到”仍属于未完成。

## 7. 测试策略及报错含义

| 结果 | 当前含义 | 维护原则 |
| --- | --- | --- |
| 失败：配置或客户端问题 | 缺少凭证、REALITY 公钥、算法不支持、内核版本不符等 | 定位解析、校验或内核接入；不能统一视作远端失效 |
| 不可用：TCP 连接失败/超时 | 该次 TCP 探测与实际代理请求均未成功 | 不能仅凭日志判定服务器永久失效 |
| 不可用：HTTPS 超时 | 在设置预算内未完成代理 HTTP/HTTPS 探测 | 保留用户预算；本项目用户明确使用 2 秒筛选，不自动延长或重试 |
| 不可用：EOF | 代理握手或传输提前关闭 | 需要结合节点配置、对应出站日志和复测判断原因 |
| 可用 | 本次代理探测成功并获得延迟 | 不等于全部应用、UDP、长期会话及 TUN 都已验收 |

批量测试沿用配置的 HTTPS 时限，TCP 探测最多为 `min(批量时限, 3 秒)`，与实际代理请求并行。TCP 结果只补充延迟和失败诊断，不拦截代理请求；即使直接 TCP 探测失败，只要代理请求成功，节点仍判为可用。Hysteria2、TUIC、WireGuard 和 MASQUE H3 跳过节点 TCP 探测；MASQUE H2、SOCKS5、HTTP/HTTPS 仍收集 TCP 数据。没有可用代理内核时，单纯 TCP 成功不能确认节点代理可用；Hysteria2/MASQUE/TUIC/WireGuard 会提示需要内核进行实际测试。

单节点与批量测试时限不同。`ProbePolicy` 的慢握手预算用于相应单测路径；不能把其中的 12 秒下限重新套到批量测试。修改此处必须运行预算、取消、暂停/恢复等回归检查。

## 9. 验证记录与测试入口

以下区分已完成的验证与仍需验收的范围；具体结果以记录的内核版本和测试环境为准。

## 10. 后续扩展流程

1. **定义边界**：说明新增的是节点协议、传输、安全层还是接管方式；确定输入格式、凭证、版本门槛及不支持的选项。
2. **贯通入口**：更新模型、单条与订阅解析、YAML、提取正则、导出及界面支持提示；不保留的关键参数应明确拒绝或记录限制。
3. **贯通运行与数据**：补内核选择、校验、配置、启动清理、TCP/UDP 测试策略、指纹、订阅合并、凭证与备份脱敏；保持现有超时预算。
4. **分层验证**：检查导入/导出往返、旧数据兼容、混合批量配置、真实内核往返和错误认证拒绝，再按需要验收公网及 TUN；记录未测项和既有失败。
5. **同步交付**：更新本文件、专项说明和 README，核对构建产物实际包含的源码与内核；不要把源码支持自动写成历史安装包已支持。

当前未作为可导入节点协议接入的例子包括 ShadowsocksR、Hysteria 1、NaiveProxy、SOCKS4/4a、TUIC v4，以及 Cloudflare WARP 的 MASQUE 专用配置。后续新增时，以模型枚举、解析入口、配置和验收证据一起更新本表。
